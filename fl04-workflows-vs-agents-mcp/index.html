01 · Concept

Workflow vs. Agent Explainer

Understanding the control-flow distinction is the foundation for classifying any AI system correctly — and for knowing when an upgrade to agentic behavior is justified.

What is an Agent? An agent is a system where the language model itself decides, at runtime, which tools to call, in what order, and when to stop. The model owns the control loop: it observes an environment state, reasons about the next action, executes a tool, evaluates the result, and repeats — dynamically re-planning until a goal condition is satisfied. No external script dictates the sequence in advance.

Fixed DAGs vs. Dynamic Reasoning Loops. A workflow is orchestrated by predetermined code: a Directed Acyclic Graph (DAG) of steps wired together by a developer, where each node runs once, in a fixed order, and passes its output to the next. An agent replaces that hard-wired graph with a reasoning loop — the "graph" is generated dynamically by the model on every turn, allowing branching, retries, and back-tracking that no static diagram could have anticipated ahead of time.

⛓ AI Workflows

Control flowPredefined, code-orchestrated
Tool executionCalled at fixed points
PathingSingle deterministic path
Feedback loopNone — one-way handoff

◇ AI Agents

Control flowModel-decided at runtime
Tool executionChosen dynamically by model
PathingBranching, variable-length
Feedback loopContinuous self-evaluation

FL-04 Classification

FL-04 is strictly a Workflow. It runs a fixed 3-step handoff sequence — each stage executes exactly once, in a predetermined order, with no autonomous back-tracking or model-driven branching.

1 · Draft→ 2 · Critique→ 3 · Revise

No step re-invokes an earlier one, and no evaluation gate decides whether to loop again — the defining trait of a workflow rather than an agent.

02 · Protocol

Model Context Protocol (MCP) Primitives

MCP standardizes how hosts, servers, and models exchange context. Each primitive is controlled by a different party in the system.

T

Tools

Model-controlled

Executable functions the model can invoke to take actions or cause mutations in the outside world.

  • Database writes
  • External API calls
  • File system mutations
R

Resources

Application-controlled

Read-only contextual data the host application attaches to a conversation on the model's behalf.

  • Config files
  • Local documents
  • Static reference data
P

Prompts

User-controlled

Standardized, reusable interaction templates a user explicitly invokes to shape a request.

  • Slash-commands
  • Pre-built templates
  • Guided workflows
03 · Upgrade Path

Evaluator-Optimizer Feedback Loop

Turning FL-04's one-way assembly line into an autonomous agent means adding a re-entrant evaluation gate wired to real MCP tools.

Draft → Critique → Evaluator (score) → Score > 9/10 ? Terminate
↺ if score ≤ 9 → re-query MCP tools → Optimizer revises → back to Evaluator
01 Dynamic re-querying: the Optimizer calls MCP tools (e.g. a linter, a search API, a style-guide resource) mid-loop instead of relying only on the original draft's context.
02 Feedback loop: the Evaluator scores each revision against a rubric and returns structured critique, which becomes the next iteration's input — closing the loop that a workflow lacks.
03 Auto-termination threshold: the loop exits automatically once the Evaluator's score exceeds 9/10, or after a max-iteration safety cap, preventing runaway looping.
